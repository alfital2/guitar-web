## Final behavior — tune-to-animate screens

- **At rest**: every pedal screen is a STILL, param-true diagram. Two
  screenshots of a resting screen 1s apart are byte-identical (proved, diff
  0.00). Idle cost per pedal per tick: one params-signature string compare.
- **While tuning**: a param change kicks that pedal's animation clock to full
  speed — the echoes replay down the train, the comb sweeps, the horn spins,
  the compressor probe rides the knee with pumping IN/OUT meters. Motion
  continues while the knob keeps moving (0.6s hold after the last change).
- **After tuning**: the clock's velocity decays ~10% per tick (~2–3s ease-out)
  until the screen parks at its final pose — a smooth slow-down, no snap-back.
- Bypassed pedals: one dimmed frozen frame, no updates even if params change.
- Hidden tab: the tick returns before any work. One shared `setInterval`
  (~12fps only while something animates; the interval stops entirely when the
  board has no entries).
- **Static poses are param-legible on their own** so a parked screen still
  reads the knobs: delay spacing/count = Time/Feedback; flanger comb density =
  Rate, tooth depth = Depth, sharpness = Feedback; vibrato breath amount/count
  = Depth/Rate; rotary motion-trail length = Speed; autopan sweep extent =
  Depth, tick count = Rate; springverb coil count = Tension; autowah ghost
  humps mark the Range extremes; compressor knee = true Threshold/Ratio math.
- **Mathematical truth unchanged**: drive/fuzz/distortion (+ octave's
  rectifier) evaluate the SAME dsp.js WaveShaper curves the audio runs
  (spy-tested + identity-tested); EQ plots its real biquad magnitude response
  (RBJ/Web Audio formulas, unit-tested flat/boost/cut).

## Collapsible pedalboard (user-requested)

The chain now folds to a slim `.board-strip`: mini pedals (the same bespoke
palette-tile art) in signal order with the AMP chip between pre/post pedals —
mirroring the amp's collapsed value strip. A chevron on the board (top-right,
like the amp's) collapses it; tapping the strip ("TAP TO EDIT ▾") expands.
Bypassed pedals render dimmed minis. State persists (`gs-board-collapsed`,
default expanded). Screenshot: `shots/viz/board-strip.png`.

## UI review — what to tune next (requested)

Real estate / focus:
1. **DONE — board collapse.** Consider a "rig bar": when BOTH amp and board
   are collapsed, dock the two strips side by side on one row (amp values +
   pedal minis) so the whole rig reads in ~60px of height.
2. **Auto-fold on transport**: when recording/playing starts, auto-collapse
   amp + board (and restore on stop). Tuning happens before the take; during
   the take the tracks deserve the space.
3. The preset browser already collapses — unify the three collapse affordances
   (same chevron component, same "TAP TO EDIT" language) so the pattern is
   learnable.
4. Settings drawer: move the Safari warning + latency hints into a subdued
   "diagnostics" disclosure; first-run users only need Input + Power.

WOW that stays smooth (fits the established perf rules — no blur/filter/scale
on moving layers, one-shot > loop, autonomous > cursor-follow):
5. **Power-on ritual**: one-shot sequence — amp tubes warm up (already
   built), then each connector arrow lights once left→right (transform-free
   opacity steps, ~600ms total). Sells "signal flows" without a loop.
6. **Tune-to-animate everywhere**: reuse the same kick/decay clock for the amp
   head — turning Gain briefly flares the tube glow; turning Reverb ripples
   the VU needle. Same zero-idle-cost pattern, big cohesion win.
7. **Knob detents**: a 1-frame brightness tick on the knob arc each step
   crossing while dragging (no timers, piggybacks on the input event).
8. **Footswitch stomp already lands** — add the same 90ms press to the strip
   minis on toggle so the collapsed view feels alive when presets change.
9. Typography: the pedal nameplates mix per-effect display fonts well, but the
   transport bar and settings still use default weights/spacings — align them
   to an 8px baseline grid and one label style (small caps, 0.12em) to make
   the "hardware" metaphor read everywhere.
10. Avoid: looping glints on every pedal simultaneously (the current stagger
    is right), traveling borders, backdrop-filter on anything that moves.

Perf posture after this change: all 32 screens idle at zero canvas work; the
single ticker parks itself; canvases are tiny (≤2x dpr) with no filters. The
remaining always-on animations are CSS-only (LED glow, staggered glint); if
the fan complains, gate the glint with `animation-play-state: paused` while
the board is collapsed (it is `display:none` there anyway).
