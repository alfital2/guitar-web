# Effects probe report

Objective audio-verification harness for the Web Audio guitar app (`tests/effects-probe.mjs`
+ `tools/effect-probe.html`, `npm run test:probe`). Renders every registered effect
(`src/effects/index.js`) at its schema defaults in a real headless-Chromium
`OfflineAudioContext` (48kHz) against a synthetic guitar-ish signal, and asserts both
"not a no-op" and a family-correct DSP signature (echo timing, modulation rate,
spectral shift, harmonic growth, gate open/close, gain-reduction). See "Harness design"
below for the signal and metrics.

## Final result

**25 PASS / 0 FAIL / 2 SKIP** (of 27 registered effects). `npx vitest run` — 297/297
green (51 files, incl. new `tests/flanger.test.js`). `npm run test:e2e` — PASS.

## Harness design

**Signal** (3.0s @ 48kHz, built and analyzed entirely in-browser so only small metric
objects cross the CDP bridge):
- 3 decaying sawtooth-ish tone bursts at 220Hz (two loud @ 0.6 amplitude, one quiet @
  0.06 amplitude for the gate check), each followed by a silent gap — gaps expose
  time-based effects (echo tails) with near-zero dry-signal noise floor.
- A 1s sustained 220Hz sine (0.8 amplitude) at the end — exposes spectral-shift effects
  (chorus/flanger/phaser/vibrato/rotary/ringmod), harmonic-growth effects
  (drive/fuzz/octave), and amplitude-envelope-rate effects (tremolo/autopan).
- compressor/limiter get a DEDICATED loud (0.92), near-instant-onset 1s tone (see below
  — the shared burst signal decays too fast, and the sustained tone's slow 20ms fade
  masks the attack transient that reveals gain reduction).

**Metrics:** whole-buffer + gap-window RMS/spectral diff (Goertzel magnitude at a
16-point frequency spread) for the no-op gate; onset-time scan for delay-family echo
timing; a 3-stage cascaded envelope follower + mean-crossing rate estimate for
tremolo/autopan; Goertzel at 2f/3f/4f for harmonic growth; early-transient-peak
comparison for compressor/limiter (see methodology note below).

**Skips (2, both documented, not failures):**
- `neuralamp` — requires a network-fetched wasm module + `.nam` model JSON posted to
  the worklet asynchronously after construction; out of scope for a single offline
  render (per the task spec).
- `looper` — its default params (`mode=Stop`, nothing recorded yet) are a genuine,
  correct no-op by design; exercising it for real needs time-varying `AudioParam`
  automation (Stop → Record → Play) across the render, which doesn't fit this harness's
  "one static default-param render" methodology. Verified structurally instead: the
  worklet module loads and the graph renders without throwing.
- `pitchshift` (also worklet-backed) DID render meaningfully and is included in the
  full PASS table — its default `-12` semitones is audibly non-neutral, unlike looper's
  default Stop state.

## Flanger fix (docs/code-review-2026-07-01.md finding #9)

**Bug:** `src/effects/flanger.js` drove `delay.delayTime` with a **bipolar** LFO:
base `0.002s` + a sine of amplitude `mapRange(depth, 0, 10, 0, 0.003)`. At `Depth=10`
the swing is `±0.003s`, so the modulated value ranges `[-0.001, 0.005]` — negative at
the trough. Web Audio silently clamps negative `delayTime` to `0`, producing an
asymmetric, distorted sweep at higher Depth (audible as a broken flange character, not
a crash — hence invisible to the audio probe's no-op/spectral checks, which both
correctly PASSED before the fix since *some* sweep was still happening).

**Verification:** rather than trying to infer sample-domain clamping from rendered
audio (unreliable — clamping to 0 doesn't produce NaN/silence/errors, just an
asymmetric sweep shape), the bug was verified **numerically** with a new focused unit
test (`tests/flanger.test.js`, using the existing `FakeAudioContext` pattern from
`tests/chorus.test.js`). The test locates the constructed `ConstantSourceNode`
(offset) + `GainNode` (LFO amplitude) feeding `delay.delayTime` — the only nodes whose
connection target is an `AudioParam` rather than another `AudioNode` — and computes
`min = staticBase + offset - swingHalf` across the full `Depth` range 0..10, asserting
`min > 0`. Confirmed the pre-fix formula (reconstructed): `min = 0.002 - 0.003 = -0.001`
at `Depth=10`.

**Fix:** unipolar LFO via an offset + amplitude pair (mirrors the `lfoOffset` pattern
already used in `src/effects/phaser.js`): a `ConstantSourceNode` sets the sweep's
center, a `GainNode` sets its half-amplitude, both feed `delay.delayTime`. New base
floor `BASE_DELAY = 0.001s`; peak-to-peak sweep width `mapRange(depth, 0, 10, 0, 0.006)`.
At any Depth, `delayTime` ranges `[BASE_DELAY, BASE_DELAY + swing]` — always positive.
At the default `Depth=5`, the new peak-to-peak width (`3ms`) matches the OLD width at
Depth=5 exactly (`0.002 ± 0.0015` = `3ms` peak-to-peak), so the audible character at the
default setting is unchanged; only the high-Depth clamping bug is fixed. `destroy()`
now also stops the new `ConstantSourceNode`.

**Tests added:** `tests/flanger.test.js` (6 tests) — graph/LFO-start assertions
(mirroring `chorus.test.js`), destroy-stops-all-sources, the Depth-range positivity
regression test (7 Depth values 0..10), and a sweep-width-preserved-at-default check.
The probe's flanger row (spectral-family signature: sustained-tone spectrum differs
from dry) passes both before and after the fix — as expected, since the bug is a
subtle sweep-symmetry issue, not an "is it doing anything" issue.

## Gate / octave verdicts (design spec §4)

**Gate:** PASS at default params, no change needed. Quiet burst (0.06 amplitude)
attenuated to `quietRatio=0.307` of its dry level (gate audibly closes); loud bursts
pass through at `loudRatio=0.906` (gate stays open). Default `threshold=2` (→ ~0.034
envelope-amplitude threshold via `mapRange`) does not need lowering.

**Octave:** the ASSIGNED signature (harmonic growth — full-wave rectification should
add 2f/3f/4f content) PASSES: `wetHarm=0.0459` vs `dryHarm=0.0006` on the sustained
220Hz tone, confirming octave-up overtones are genuinely present. Per the task's
explicit instruction ("if octave shows no sub/harmonic shift signature, report it — do
NOT redesign it"), no code change was made to octave for this signature, since it
passes.

**Additional finding (reported, not fixed — out of scope per "do NOT redesign
octave"):** the probe also caught a real, separate correctness bug via an
*informational* check (does not gate PASS/FAIL, since it's outside the task's assigned
octave signature): with **zero input** (the silent gap after a burst), the octave
effect emits a sustained **DC-ish offset of RMS ≈0.279** — nearly 200x the near-zero
noise floor that `drive`/`fuzz` (the other two feedforward WaveShaper effects) show in
the identical silent window (`0.0015`–`0.0055`). Root cause: `makeRectifierCurve`
in `src/dsp.js` computes `curve[i] = depth * (Math.abs(x) * 2 - 1) + (1 - depth) * x`,
which at `x=0` evaluates to `-depth` (default octave `depth=0.7` → `-0.7`), NOT `0` —
unlike `makeSoftClipCurve`/`makeHardClipCurve`, which both explicitly recenter so
`f(0) = 0`. This constant offset flows through octave's `tone` lowpass + `output` gain
(`0.7 * 0.4 ≈ 0.28`, matching the measured `0.279` almost exactly) and would be audible
as a persistent hum/thump whenever the guitarist isn't actively playing (any note
decay, pick-hand mute, or silence between phrases). **Recommended follow-up (not
performed here):** fix `makeRectifierCurve` to satisfy `curve(0) = 0` for all `depth`,
e.g. `depth * (Math.abs(x) * 2 - 1) - depth * (-1)` style recentering (same pattern as
the other two curve functions) — this is a `src/dsp.js` math fix, not a default-param
change, so it was left unfixed per this task's explicit scope restriction.
